出口
接口名 显示名 源IP（填 auto 自动获取） mark 值（逗号分隔） 类型

接口名 = 路由器上的网络接口，用于绑定出口发包。点输入框会列出本机现有接口 （实时读的，后面带当前 IPv4 地址），也可以直接手打。
显示名 = 看板上显示的名字，不能有空格。
源IP = 测 HTTP 目标时用来临时加一条源地址策略路由。DHCP 出口必须填 auto， 采集时自动读接口当前地址——地址一变，写死的值就挂出一条不匹配任何流量的空规则， 包从本接口出去、回包却走默认路由回来，TCP 握手会随机失败（表现为「时通时不通」）。 自带出口路由的接口（如 PPPoE）留空即可。
mark 值 = conntrack 里的 fwmark，「实时TCP流」页靠它判断每条连接走的哪个出口。 填错只会让那一页的出口标错，不影响延迟曲线。可以在路由器上跑 ip route get 1.1.1.1 mark 256 逐个确认。
类型 = 这个出口测哪一类目标。看板按出口分标签页，类型决定那一页里 画哪些曲线：IPv4 + IPv6 两组都画，仅 IPv4 就只画 v4 目标， 仅 IPv6 只画 v6 目标。只走 v6 的接口选「仅 IPv6」能省掉一半采集时间。

监测目标

每个出口都会把这里所有目标各测一遍，目标越多一轮采集越慢 （一轮 ≈ 目标数 × 出口数 × CURL_TIMEOUT）。名字用来在统计表里分组， 改名字等于把历史数据切成两段，改完想合并得连 history.log 一起改。

采集参数

改采集间隔后要重启服务才生效（守护进程启动时读一次）： 在路由器上跑 /etc/init.d/linemon restart，或者重启路由器。
KEEP_LINES 直接决定 history.log 多大、看板每次拉多少数据：1440 行约 760KB。

推送目标
关闭 — 只采集，不推送

判定与去抖
推送「已恢复」

不可达或延迟超过 ALERT_MAX_MS都算异常，单个目标连续 ALERT_DEBOUNCE 次异常才推第一条，避免把偶发抖动（移动线路每隔几十分钟会有一次 1 秒左右的尖峰）当成故障。推过之后保持沉默，直到恢复正常，或者过了 ALERT_COOLDOWN 再提醒一次。同一轮里多个目标出问题会合并成一条消息发出去。
ALERT_COOLDOWN=0 表示只在首次异常和恢复时各推一条。
当前移动和电信的 IPv6 目标常年不可达，所以范围默认 v4，不然会一直响。

测试

走的是路由器上保存好的配置，所以先点下面的「保存并生效」再点测试。
调完之后可以在路由器上跑 /usr/bin/lm_alert.sh --status 看各目标当前是正常还是已告警。

统计表配色阈值

只影响看板统计表的颜色，不参与采集、也不影响告警。单位毫秒。最大延迟看有没有偶发卡死， 波动σ看这条线路稳不稳。各目标基线差异大（DNS 一二十毫秒、网站几百毫秒）， 按自己线路的实际水平调；超出 WARN 标橙色，超出 BAD 标红色。
