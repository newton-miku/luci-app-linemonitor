出口
接口名 显示名 源IP（填 auto 自动获取） mark 值（逗号分隔） 类型 监测目标

接口名 = 路由器上的网络接口，用于绑定出口发包。点输入框会列出本机现有接口 （实时读的，后面带当前 IPv4 地址），也可以直接手打。
显示名 = 看板上显示的名字，不能有空格。
源IP = 测 HTTP 目标时用来临时加一条源地址策略路由。DHCP 出口必须填 auto， 采集时自动读接口当前地址——地址一变，写死的值就挂出一条不匹配任何流量的空规则， 包从本接口出去、回包却走默认路由回来，TCP 握手会随机失败（表现为「时通时不通」）。 自带出口路由的接口（如 PPPoE）留空即可。
mark 值 = conntrack 里的 fwmark，「实时TCP流」页靠它判断每条连接走的哪个出口。 填错只会让那一页的出口标错，不影响延迟曲线。可以在路由器上跑 ip route get 1.1.1.1 mark 256 逐个确认。
类型 = 这个出口测哪一类目标。看板按出口分标签页，类型决定那一页里 画哪些曲线：IPv4 + IPv6 两组都画，仅 IPv4 就只画 v4 目标， 仅 IPv6 只画 v6 目标。只走 v6 的接口选「仅 IPv6」能省掉一半采集时间。
监测目标 = 这个出口要监测哪些目标，点一下弹出勾选面板。 留空 = 全部目标都测（新加的目标默认所有出口都测）。这里和「监测目标」页里 每个目标的「监测线路」是同一份数据，两边勾的都是它，改哪边都一样。
如果只想让组网线路测对端子网、外网线路别去碰它，就点开外网出口的勾选面板， 把内网目标取消掉。取消过之后这个出口就有一份显式清单，之后新加的目标不会 自动进这条线路 —— 想让它测就再勾一次。

监测目标
类型 分组 名称 地址 / 域名 监测线路

类型决定用哪种方式测：ICMP 用 ping（DNS 这类不封 ICMP 的）， HTTP 用 curl 测 TCP 连接耗时（封 ICMP 的网站/游戏服务器）， IPv6 用 ping6（每条出口用它自己的 v6 源地址）。
分组只是看板统计表里的分类标签（显示成名字前面的灰字），不决定谁测它，可以留空。
名称是 history.log 里的曲线键，改名等于把历史数据切成两段， 改完想合并得连 history.log 一起改。不能有空格和逗号。
监测线路和上面每个出口的「监测目标」是同一份数据 —— 这里勾哪个出口， 等于在那个出口上加一条目标；取消勾选等于从那个出口的清单里摘掉。两边永远一致。

采集参数

改采集间隔后要重启服务才生效（守护进程启动时读一次）： 在路由器上跑 /etc/init.d/linemon restart，或者重启路由器。
KEEP_LINES 直接决定 history.log 多大、看板每次拉多少数据：1440 行约 760KB。

推送目标
关闭 — 只采集，不推送

判定与去抖
推送「已恢复」

异常分两级，各自只推一条，不会反复刷屏：
不可达（ping 全丢 / 网站连不上）= 线路断了 —— 推一条；恢复后再推一条「已恢复」。
丢包 ≥ ALERT_LOSS_PCT 或 延迟 > ALERT_MAX_MS = 能通但质量差 —— 推一条提醒； 恢复正常不推（丢包抖动太频繁，报恢复只会更吵）。
单个目标要连续 ALERT_DEBOUNCE 次处于同一等级才推第一条，避免把偶发抖动 （移动线路每隔几十分钟会有一次 1 秒左右的尖峰）当成故障。 ALERT_COOLDOWN=0 表示同等级不再重复推；设成 3600 就是没好转时每小时再提一次。
同一轮里同类多个目标会合并成一条消息发出去。
当前移动和电信的 IPv6 目标常年不可达，所以范围默认 v4，不然会一直响。

测试

走的是路由器上保存好的配置，所以先点下面的「保存并生效」再点测试。
调完之后可以在路由器上跑 /usr/bin/lm_alert.sh --status 看各目标当前是正常还是已告警。

统计表配色阈值

只影响看板统计表的颜色，不参与采集、也不影响告警。单位毫秒。最大延迟看有没有偶发卡死， 波动σ看这条线路稳不稳。各目标基线差异大（DNS 一二十毫秒、网站几百毫秒）， 按自己线路的实际水平调；超出 WARN 标橙色，超出 BAD 标红色。
